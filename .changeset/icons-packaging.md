"@vega-ui/icons": minor

Exports map, generated barrel, statically tree-shakeable icon modules

**`exports` map with wildcard subpaths.** `@vega-ui/icons` was the only package without an `exports` map — just `main`/`types`/`files`. That loses the ESM-only guarantee, leaves module-format behavior ambiguous in Node 20+, and gives consumers no way to import a single icon without pulling the whole barrel (which re-exports all of lucide-react plus 250+ flags).

- added `exports` with the same `.` entry shape as the other packages (`source` + `import.types`/`import.default`), plus `module` field
- added wildcard subpath exports mirroring the barrel names: `@vega-ui/icons/FlagUS` (`./Flag*` → `dist/assets/flags/`), and `./*` for custom icons (`@vega-ui/icons/double-arrow-left` → `dist/assets/icons/`) — each resolves to its own module in `dist`, bypassing the barrel entirely for guaranteed tree-shaking; new custom icons get a subpath automatically, no `exports` edit needed
- subpath imports are typed via a shipped `svg.d.ts` (`FC<SVGProps<SVGSVGElement>>`)
- note: an `exports` map locks down undocumented deep imports like `@vega-ui/icons/dist/index.js` — anyone relying on those must switch to the documented entry points

**Generated barrel; new `TrainsSideIcon` export.** `src/index.ts` is now generated by `scripts/generate-icons.mts` from the SVG files in `src/assets/{icons,flags}` (runs on every build, or manually via `pnpm generate`). Adding a new icon or flag is now just dropping an SVG into the right folder — no manual barrel or `exports` edits. As a side effect the generator picked up `trains-side.svg`, which existed in assets but was never wired into the barrel — `TrainsSideIcon` (and the `@vega-ui/icons/trains-side` subpath) is now exported.

**Dropped `forwardRef` from generated icon components — modules are now statically tree-shakeable.** svgr-generated flag/icon modules ended with a bare `forwardRef(SvgComponent)` call, which statement-level tree-shaking must treat as a potential side effect. Module-level shaking already worked (`sideEffects: false` + `preserveModules` — verified with esbuild and rollup: importing one icon from the barrel pulls only that icon), but pipelines that ignore the `sideEffects` field would retain every flag.

Since the package requires React 19 (`peerDependencies`), `forwardRef` is unnecessary: `ref` arrives as a regular prop and reaches the `<svg>` element through the props spread. svgr's `ref: true` option was removed, so each module is now a single arrow-function declaration with no top-level calls — side-effect free by construction, no `/*#__PURE__*/` annotations needed.

Verified: ref attaches to `SVGSVGElement` in Chromium/Firefox/WebKit (browser test), SSR render unchanged, barrel imports stay fully shaken (single lucide icon ≈ 2–3.5 kB, single flag ≈ 7 kB), 57 Icon/IconButton browser tests pass.
