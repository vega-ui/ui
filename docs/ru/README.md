# Документация VegaUI

Этот каталог — отправная точка для документации проекта за пределами Storybook. Он объясняет, как устроен VegaUI, как подключить его к приложению и как использовать каждый компонент в продакшен-коде.

## Источники истины документации

- `packages/ui/src/*`: публичный API, экспортируемые типы и модель композиции
- `*.stories.tsx`: реалистичные примеры использования и визуальные состояния
- `__tests__/*.browser.test.tsx`: поведение при взаимодействии и пограничные случаи
- `packages/*/README.md`: заметки по установке и настройке отдельных пакетов

## Структура

- `getting-started.md`: установка, стили, шрифты и локальная разработка
- `architecture.md`: устройство монорепозитория и зоны ответственности пакетов
- `glossary.md`: общая терминология документации компонентов
- `families/`: навигация по группам связанных компонентов, помогающая сделать выбор
- `styling/`: глобальные темы, токены и модель CSS-переменных
- `i18n.md`: даты в формате ISO, корневые пропсы `locale` и `calendar` и адаптеры календарных систем из `@vega-ui/i18n`
- `components/`: использование компонентов, заметки об API, экспорт типов и пограничные случаи
- `components/structure.md`: заявленная файловая структура документации компонентов
- `component-template.md`: шаблон для документирования оставшихся компонентов

## Структура документации компонента

Документация компонентов теперь разложена по каталогам `docs/components/<component>/`.

Каноническая структура описана в `docs/components/structure.md`.

Основные файлы:

- `index.md`: входная страница, назначение, минимальная композиция, варианты, связанные документы
- `examples.md`: примеры сценариев, сгруппированные по общей таксономии
- `api.md`: пропсы, экспортируемые части, типы и модель состояния
- `styling.md`: CSS-переменные, точки настройки темы и рекомендации по переопределению
- `accessibility.md`: контракт клавиатуры, фокуса, подписей и скринридеров
- `comparison.md`: когда выбрать этот компонент вместо похожих
- `patterns.md`: переиспользуемые паттерны интеграции в продукт
- `troubleshooting.md`: типичные сбои, диагностика и исправления
- `anatomy.md`: структура составного компонента, обязательные части и недопустимые композиции

Набор обязательных файлов задают профили документа из `docs/components/structure.md`:

- `primitive`: `index.md`
- `form-control`: `index.md`, `examples.md`, `api.md`, `accessibility.md`
- `compound`: `index.md`, `anatomy.md`, `examples.md`, `api.md`
- `advanced interactive`: полный набор файлов, включая `styling.md`, `comparison.md`, `patterns.md` и `troubleshooting.md`

## Правила документации

- Отдавайте предпочтение примерам, которые совпадают с существующими историями Storybook.
- На каждой странице компонента должен быть хотя бы один конкретный пример.
- Для компонентов, с которыми работает потребитель, лучше 2–4 примера на основе сценариев, чем один минимальный фрагмент.
- Заголовки сценариев в разделе «Ещё примеры» по возможности используют общую таксономию:
  `Basic`, `Controlled/Stateful`, `Form/Integration`, `Layout/Overlay`, `Error`, `Disabled`, `Edge`.
- На каждой странице компонента перечисляйте поддерживаемые варианты или варианты композиции.
- Описывайте паттерны композиции, а не только плоские списки пропсов.
- Указывайте разницу между контролируемым и неконтролируемым поведением, когда это важно.
- Включайте пограничные случаи доступности и интеграции, если они влияют на использование API.
- Добавляйте короткий раздел «Частые ошибки» о предсказуемых ошибках интеграции.
- Держите примеры в соответствии с реальными экспортами `@vega-ui/react`.
