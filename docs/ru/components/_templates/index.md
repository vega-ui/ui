# ComponentName

Используйте этот файл как главную страницу каждого компонента.

## Рекомендуемые разделы

## Профиль документа

Используйте ровно одно из значений:

- `primitive`
- `form-control`
- `compound`
- `advanced interactive`

## Кратко

Один короткий абзац о роли компонента в дизайн-системе.

## Импорт

```tsx
import { ComponentName } from '@vega-ui/react';
```

## Экспортируемые типы

- `ComponentProps`
- `ComponentVariant`
- `ComponentSize`

Перечисляйте только публичные типы, важные для потребителя.

## Минимальная композиция

Используйте `Basic Usage` для простых компонентов и `Minimal Composition` для составных.

```tsx
// minimal working example
```

## Обязательные части

Добавляйте только для составных компонентов.

- `Root`: за что отвечает
- `ChildPart`: что рендерит

## Необязательные части

Добавляйте только для составных компонентов.

- `OptionalPart`: когда помогает и когда её можно опустить

## Порядок композиции

Добавляйте только для составных компонентов.

1. `Root`
2. `Required child`
3. `Optional child`

## Варианты

- визуальные варианты
- варианты размера
- варианты поведения, когда они актуальны

## Пограничные случаи

- контролируемое и неконтролируемое поведение
- отключённое состояние и режим только для чтения
- заметки об интеграции с оверлеями, формами или асинхронными данными

## Типичные ошибки

- предсказуемые ошибки интеграции
- неподдерживаемые формы значения
- пропущенные части композиции

## Рекомендации

- Держите `index.md` коротким и удобным для навигации.
- Размещайте здесь минимальную безопасную композицию, а не все сценарии.
- Выносите тяжёлые паттерны, таблицы API и диагностику в отдельные файлы.
