# ContextMenu: доступность

## Подписи

- У `MenuContent` в `ContextMenu` нет `aria-labelledby`, потому что нет кнопки, которая дала бы ему имя. Передайте `aria-label` или `aria-labelledby` в `MenuContent` сами и назовите объект, с которым работает меню, например имя файла. Компоненты сами подписи не ставят.
- Дайте имя каждой `MenuRadioGroup` и каждой `MenuGroup` с заголовком — через `aria-labelledby`, указывающий на заголовок, или через `aria-label`.
- Кнопке из одной иконки, которая открывает те же действия в `Menu`, например `Button` с `square` и «⋯», нужен `aria-label`, который называет объект.

## Поведение фокуса

- При открытии фокус переходит на первый пункт меню.
- Меню, открытое клавишей контекстного меню или Shift+F10, появляется у элемента в фокусе: браузер передаёт точку этого элемента. Эти клавиши открывают меню, только пока фокус внутри области, поэтому область без фокусируемых элементов открывается только указателем; держите её действия доступными с видимой кнопки или из [Menu](../menu/).
- У пунктов `tabIndex={-1}`: фокус по ним переносят только стрелки, Home, End, поиск при наборе и указатель, как в `Menu`.
- Библиотека не переносит фокус при закрытии меню: браузер возвращает его на элемент, который был в фокусе, когда меню открылось, например на кнопку строки. Если перед правым щелчком по области ничего не было в фокусе, фокус уходит на страницу.
- Tab и Shift+Tab закрывают меню и переносят фокус дальше по странице.
- Во вложенном меню Escape и стрелка влево (вправо на странице с письмом справа налево) закрывают только его и возвращают фокус на пункт, который его открыл.

## Семантика для скринридеров

- У `ContextMenuTrigger` нет роли, `aria-haspopup` и `aria-expanded`: область — не кнопка меню, и скринридер объявляет её содержимое как есть.
- `MenuContent` — `menu`; `MenuItem` — `menuitem`, `MenuCheckboxItem` — `menuitemcheckbox`, `MenuRadioItem` — `menuitemradio`, оба последних с `aria-checked`. `MenuSubmenuTrigger` — `menuitem` с `aria-haspopup="menu"`.
- У отключённых пунктов `aria-disabled="true"`: о них сообщается как о недоступных, но они остаются фокусируемыми, как в `Menu`.

## Риски доступности

- Действие есть только в контекстном меню: его не найти глазами, многие пользователи никогда не нажимают правую кнопку, а на macOS нет клавиши контекстного меню. Каждое действие должно быть доступно и по-другому, например видимой кнопкой или `Menu` на кнопке «Ещё».
- `MenuContent` без `aria-label` или `aria-labelledby`: у меню нет имени.
- Область без фокусируемых элементов: с клавиатуры её меню не открыть совсем.
- Контролы или длинный текст внутри меню: скринридер в меню ждёт только пункты, а стрелки до остального не доходят.
