# DateTimeField: доступность

Поле следует паттерну WAI-ARIA [Date Picker Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/): текстовый input для ввода, кнопка-триггер и диалог с календарём и колёсами времени для выбора.

## Подписи

- Назовите input видимым `Label` (`htmlFor`) или через `aria-label` / `aria-labelledby` на `DateTimeFieldInput`.
- Назовите `DateTimeFieldTrigger` только с иконкой через `aria-label`, например «Выбрать дату»; триггер с текстом называется своим текстом. Поле не добавляет подписей само.
- Задайте `role="dialog"` у `PopoverContent` и назовите его через `aria-label` или `aria-labelledby`, чтобы календарь и его кнопка времени были одним диалогом. Назовите кнопку времени через `aria-labelledby` из видимой подписи «Время» и самой кнопки, чтобы она читалась как «Время 18:30»; назовите вложенный диалог, `WheelPicker` и каждую колонку, например «Часы» и «Минуты».

- Вводить можно, не открывая календарь. Внутри календаря навигация только перемещает фокус; значение меняется, только когда выбран день.
- Ввод проверяется в календарной системе поля: одиночная цифра, с которой не может начинаться двузначный сегмент, дополняется нулём, заполненные сегменты ограничиваются (день — длиной месяца), а полное значение вне `min` / `max` остаётся как введено и делает input невалидным.

## Поведение фокуса

- У триггера `aria-haspopup="dialog"`; он открывает календарь через нативный `popovertarget`, который сообщает `aria-expanded` и связанный всплывающий элемент.
- При открытии фокус переходит в сетку дней: на выбранный день, иначе на сегодня (ограниченное `min` и `max`), иначе на первый доступный день. Календарь открывается на месяце этой даты.
- Выбор дня (клик, <kbd>Enter</kbd> или <kbd>Space</kbd>) записывает его в поле со временем (без него — с полуночью) и оставляет попап открытым с фокусом на дне, как нативный пикер `datetime-local`; <kbd>Tab</kbd> переводит фокус на кнопку времени, которая открывает колёса во вложенном поповере. <kbd>Escape</kbd> там закрывает только колёса и возвращает фокус на кнопку времени.
- <kbd>Escape</kbd> и клик снаружи закрывают попап без изменений; браузер возвращает фокус на триггер. В Safari клик мышью не переводит фокус на кнопку, поэтому после закрытия попапа, открытого мышью, фокус возвращается на body страницы; при активации с клавиатуры он возвращается на триггер.
- Отступление от модального диалога APG: попап — немодальный `popover="auto"`. <kbd>Tab</kbd> может вывести из него фокус, а сам попап остаётся открытым до <kbd>Escape</kbd>, клика снаружи, нажатия на триггер или открытия другого поповера. Так страница остаётся доступной, как с нативными календарями браузеров.
- Чтобы попап с одним календарём закрывался после выбора, сделайте `open` у `Popover` контролируемым и выставляйте `false` в `onChangeValue` у `DateTimeFieldCalendar`.

## Семантика для скринридеров

- Ожидаемый формат должен сообщаться в подписи, подсказке или тексте ошибки, а не только в placeholder.
- Сетку дней называет `CalendarHeading`, который вежливо объявляет показанный месяц при его смене.
- С `readOnly` на корне input получает `readonly`, а сетка дней — `aria-readonly="true"`: календарь открывается, чтобы показать дату, навигация работает, а выбор не меняет значение.
- Поле никогда не ставит `aria-invalid` само. Вид ошибки следует за `:user-invalid` и `[data-user-edited]:invalid`, поэтому неполное значение, значение вне диапазона или недоступный день помечаются, как только пользователь изменил поле и ушёл из него или попытался отправить форму; для ошибки, о которой знает только приложение, ставьте `aria-invalid` на `DateTimeFieldInput` вместе со своим сообщением об ошибке.

## Семантика формы

- `DateTimeFieldInput` отправляет показанный текст под своим `name`, как нативное текстовое поле; значение `YYYY-MM-DDTHH:mm[:ss]` приходит из `onChangeValue`.
- `disabled` и `readOnly` на корне работают как нативные атрибуты: отключённое поле (в том числе внутри отключённого `<fieldset>`) не отправляется, поле только для чтения — отправляется.
- Input сообщает нативную валидность через `setCustomValidity` с сообщением браузера: дата без полного времени, значение раньше `min` или позже `max` и день из `disabledDates` невалидны, поэтому работают `:invalid`, `reportValidity()` и проверка браузера при отправке. `required` на `DateTimeFieldInput` работает нативно. Поле владеет `setCustomValidity` своего input; своё сообщение показывайте из `onInvalid`.
- Сброс формы восстанавливает `defaultValue`, если поле не контролируемое.

## Риски доступности

- Ожидаемый формат даты указан только в placeholder.
- Триггер или диалог остались без имени.
- Календарь открывается внутри другого оверлея без совместной проверки фокуса и закрытия.
