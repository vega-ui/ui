# Select: сравнение

## Быстрое правило выбора

Выбирайте `Select`, если верно всё перечисленное:

- выбор одиночный
- значение — `string` или `number`
- набор вариантов лучше скрыть, чем показывать постоянно
- важны участие в нативной форме или семантика поля

Выбирайте другой элемент, если видимость, бинарное состояние или более богатое содержимое с действиями важнее компактного поведения поля.

## `Select` и `SegmentedControl`

Используйте `Select`, когда:

- вариантов много
- места мало
- варианты не обязательно показывать всё время

Используйте `SegmentedControl`, когда:

- вариантов всего несколько
- пользователю полезно видеть все варианты сразу
- переключение между вариантами должно ощущаться мгновенным

Компромисс:

- `Select` экономит место, но скрывает варианты
- `SegmentedControl` облегчает обнаружение вариантов, но занимает ширину макета

## `Select` и `Radio`

Используйте `Select`, когда:

- список вариантов длинный
- поле находится в плотной форме
- элемент должен оставаться компактным

Используйте `Radio`, когда:

- набор вариантов короткий
- пользователи должны напрямую сравнивать все доступные варианты
- явная видимость одиночного выбора важнее компактности

Компромисс:

- `Select` плотнее
- `Radio` нагляднее для сравнения

## `Select` и `Checkbox`

Используйте `Select`, когда:

- пользователь должен выбрать ровно один вариант
- значение должно вести себя в форме как скалярное поле

Используйте `Checkbox`, когда:

- взаимодействие бинарное
- каждый элемент представляет независимый выбор «да» или «нет»

Не заменяйте группы из нескольких чекбоксов одним `Select`, если модель продукта на самом деле не подразумевает одиночный выбор.

## `Select` и `Switch`

Используйте `Select`, когда:

- пользователь выбирает из нескольких значений
- выбранное значение должно сохраняться как одно поле

Используйте `Switch`, когда:

- взаимодействие — мгновенное включение или выключение
- настройка меняется напрямую, без выбора из списка

Компромисс:

- `Select` — для выбора из перечисления
- `Switch` — для бинарного состояния

## `Select` и `Popover`

Используйте `Select`, когда:

- основная задача — выбрать значение
- нужны навигация по вариантам с клавиатуры и семантика значения

Используйте `Popover`, когда:

- содержимое — не поле одиночного выбора в первую очередь
- оверлей содержит действия, справочный текст или собственный интерфейс, а не семантику списка

## Выбирайте этот компонент, когда

- выбор одиночный
- значение должно вести себя как одно компактное поле
- набор вариантов настолько длинный, что постоянно видимые элементы добавили бы шума
- важны участие в форме или плотный макет

## Не выбирайте этот компонент, когда

- пользователю полезно видеть все варианты сразу
- взаимодействие бинарное, а не выбор из перечисления
- содержимое оверлея на самом деле не является полем
- модель значения опирается на объекты, а не на скалярные ключи
