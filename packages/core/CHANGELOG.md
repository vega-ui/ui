# @vega-ui/core

## 3.0.0

### Minor Changes

- fa3d436: New `Combobox`: a text input with a list of suggestions, following the WAI-ARIA combobox pattern.

  - `Combobox` holds the picked option in `value`, `defaultValue` and `onChangeValue`, and the list state in `open`, `defaultOpen` and `onChangeOpen`. Editing or clearing the text calls `onChangeValue(null)`.
  - `ComboboxInput` goes inside a `TextField` and keeps its text as a plain input value, controlled with `value` and `onChange` or uncontrolled. Picking an option writes the option label and fires `input`, so `onChange` receives it.
  - `ComboboxListbox` is the list, a native `popover="manual"` element shown while the combobox is open and has options. Put `ListboxOption` and `ListboxGroup` in it; the app filters the options itself.
  - `ComboboxTrigger` is a button inside the `TextField` that opens and closes the list for the pointer and touch. It stays out of the tab order and keeps the focus in the input. `ComboboxIcon` goes inside it: a chevron by default, sized like the icon of a `Select` and marked `data-open` while the list is shown.
  - `autocomplete` on the root sets `aria-autocomplete` on the input: `list` by default, when the app filters the options by the text, `none` when the options stay the same, and `both` to also complete the typed text with the label of the first matching option, the part after the typed text selected, or `inline` to only complete it, with the list left closed while typing. Typing goes over the completed rest, `Backspace` removes it, the arrow keys write the label of the option they reach with the same rest selected, `Enter` picks the option, `Escape` puts the typed text back, and leaving the input keeps the completion. The text before the selection is what the user typed, so the app filters by it.
  - The active option is marked `aria-selected`, and the picked one while no option is active. Hovering an option only highlights it and leaves the active option to the keyboard, as in the WAI-ARIA examples.
  - Typing opens the list without an active option. `ArrowDown` and `ArrowUp` open it at the first or last option and move through it, the trigger and `Alt+ArrowDown` open it scrolled to the picked option without an active one, `Enter` and `Alt+ArrowUp` pick the active option, `Escape` closes the list and clears the text when the list is closed, and any key left to the input, like `ArrowLeft`, `ArrowRight`, `Home`, `End` or `Backspace`, returns to the text without closing the list, even when the caret cannot move. `Enter` without an active option and `Escape` with nothing to clear reach the form and the page.
  - `@vega-ui/widgets/combobox` exports the framework-free widget, and `@vega-ui/widgets/listbox` exports the `activeExists` invariant it shares with `Listbox` and `Select`.
  - `@vega-ui/core` writes the selection of `act.setText` before it dispatches `input`, so an `onChange` reads the selection along with the text.
  - `@vega-ui/core` looks only at added nodes to follow a reorder of the registered items, so rendering a long list down to a few options no longer checks every removed node against every remaining item.
  - `@vega-ui/core` adds the `text.key` input: a widget that declares it hears the keys it yields to a text field inside its root, such as the caret keys and typed characters, without preventing them.

- cef5d19: New package `@vega-ui/core` holds the logic of composite widgets, written as one pipeline with no dependency on React or the DOM: `event → normalize → step(state, input) → { state, actions } → output(state) → DOM`. The adapter does the first and the last arrow; everything in between is pure and runs in node.

  - `state({ options, owns, internal, observes, collection })` declares the shape of a widget's state. `controlled(fallback, initial)` is a value the parent may control through `x`, `defaultX` and `onChangeX`, with an optional `initial(options)` that starts it from the other options in place of `defaultX`; `internal(fallback)` is a value only the widget and its output see; `matching(part, selector)` is a value the browser owns, like whether a popover is open, that the adapter reads before every dispatch, so the browser wins over the parent and the widget. The shape gives one typed field per value (`shape.active.get(state)`, `shape.active.set(state, key)`), a reader per option (`shape.options.mode`), and `shape.part(select, render)` for the output. Every value takes a name of its own: a name the snapshot or the shape already uses, like `id`, `focused` or `create`, the name of another value, or an option named like an owned value is a type error. A snapshot is plain data: the options, the collection, the `id`, the running timers, whether the widget is focused, the observed values and the owned and internal values; `idOf(state, part, key)` builds an element id
  - `source({ key, disabled, label })` turns the items of the options into a collection, reused while the items array is the same: `order`, `index`, `disabled` and `labels` as data, and the functions `collection.next`, `previous`, `first`, `last`, `nearest`, `between`, `selectable` and `findByLabel` over it, all skipping disabled items
  - Inputs are values, not strings: `key.arrowDown`, `key.with(key.a, mod.mod)`, `key.printable` for any single character, `nav.forward` / `backward` / `first` / `last` / `pageForward` / `pageBackward` as the logical directions the adapter builds from the arrows, the orientation and the writing direction (`toNav`), plus `nav.up` / `down` in a grid, where the arrows of both axes are directions, `pointer.down` / `press` / `drag` / `dragOver` / `release` / `cancel` / `hover`, `focus.enter` / `move` / `leave`, `text.change`, `browser.toggle` / `cancel` / `close` / `submit` / `reset` / `animationEnd`, `measure.done` for the answer to `act.measure`, `timer(name)` and `command(name)` for an input a framework sends itself, like an imperative `focus(key)`, and `lifecycle.connect` / `lifecycle.options` for the moment the adapter is connected and for a change of a value the parent controls or of an option the shape names in `follows`, like the page a scroller follows, with the names of the changed options in `changed`. A typo is a type error, `input.key` is typed by the key of the collection, and `defineInput(type, name)` declares an input of your own. A pointer or key input carries the item `key` and the named `part` it hit, so a step tells a press on the trigger from a press on an option, `inside` when the event came from a control inside the item, like a button in a grid cell, so a step leaves those to the control, and `content` when the item holds focusable content, so a step sends the focus into it; a `command` carries `keys`, a list of keys, like the cells of a page that scrolled into view
  - A step is `(state, input) => handled(next, actions) | keep(next, actions) | stop(next) | undefined`: handled prevents the browser default, keep leaves it, undefined passes the input on. `listening(inputs, step)` declares the inputs a step reads from the browser, the widget collects them as `listens`, and the adapter listens only to the events that give one of them, plus the focus, and delivers a key only when a step declares it or the direction it becomes, reading the writing direction only for a key RTL changes, so a key no step reads stays with the browser; a command, a timer, a lifecycle input or an input of your own needs no declaration. The widget runs its steps in order and the first answer wins. Actions are data the adapter executes after the state is committed: `act.focus(key, { preventScroll, focusVisible })`, where `focusVisible: false` keeps the keyboard focus ring off a focus the pointer moved, like the item under the pointer in a menu,, `focusInside(key, 'first' | 'next' | 'previous')` for the focusable content of an item, `focusPart(part)`, `reveal`, `click`, `timer`, `cancelTimer`, `showPopover`, `hidePopover` and `send(part, input, payload)`, which delivers an input to the widget whose root is that part, so a widget drives a widget inside it, like a calendar focusing the day of its day grid, `sendAt(key, input, payload)`, which delivers an input to the widget whose root is the item `key` or holds it, like a menu checking the checkbox item or the radio group an item belongs to, and `measure({ name, parts, items, rect, scroll, styles, viewport })`, which the adapter runs after the DOM shows the new state, reading every request first and then answering each with a `measure.done` input of plain numbers, so geometry is data a step tests in node. `awaitAnimations(part)` waits for the animations the part runs once the DOM shows the new state, read with `getAnimations()`, and answers with `browser.animationEnd` and the `part`, also at once when none runs, so a closing popover or section is hidden when its animation really ends. An owned field tells whether the parent controls it, `shape.open.controlled(state)`, so a step hides a popover on a close request only when no parent can keep it open. A `browser.toggle` input carries the `part` whose own toggle it is, so a widget tells its popover from one nested inside. The adapter follows `cancel`, `close` and `submit` for a native `<dialog>`: `browser.cancel` and `browser.close` carry their `part`, and `handled` prevents a cancel; `browser.submit` carries the `part` of the form, its method as `to` and the `value` of the submitter. A press on the backdrop of a modal dialog carries `backdrop`. `act.showModal(part)` shows a dialog and answers with `browser.toggle` once it is shown, also in browsers without dialog toggle events, and `act.closeDialog(part, returnValue)` closes it. `awaitAnimations` waits for the animations of the element and its pseudo-elements, like `::backdrop`, not of its children. Actions are typed by the key of the collection: a step is `Step<S, K>`, with `K` the key of the state by default, so a fragment generic over its state still returns actions of its own key
  - `defineWidget({ state, step, output, invariants })` keeps the type of `output`, so `widget.output.root` renders the attributes its `shape.part` declares, and `createWidget(widget, options, { id, strict, onRepair, onError, onDispatch })`, where `id` is required and comes from the framework, so the ids of the parts are the same on the server and the client: every dispatch is a transaction, a step that throws leaves the state as it was, each invariant is checked after every commit, from the first snapshot on: one a step breaks while it held throws in strict mode and is repaired otherwise, so a value the parent controls against an invariant blames no later step, one the options break is repaired in strict mode too, without `onChangeX`, and `repair(state, before)` gets the snapshot before the commit, a repair never writes a value the parent controls, `onDispatch` traces every transaction as `{ input, answer, actions, before, after }`, `setOptions` returns the actions of the `lifecycle.options` it dispatches when the parent changes a controlled value, a changed owned value calls its `onChangeX` once and keeps the new value until the next `setOptions` brings the parent's answer, so a controlled value renders once per change, `setOptions` never calls `onChangeX`, and `render(part, key)` returns the previous attributes while the selected inputs of the part are the same
  - `setOptions` never calls an `onChangeX`: the parent sets options while it renders, so a step answering `lifecycle.options` follows them with what it shows and never changes an owned value; a strict widget refuses one that does with an error
  - Fragments are steps any widget composes: `roving({ active, strategy, hover, page })` moves the active key with the logical directions and on pointer down, under the pointer with `hover`, and by `page` items on PageUp and PageDown, with `focus` or `activedescendant`; `selection({ value, active, anchor, mode, strategy, keys })` follows the APG listbox: a press or one of `keys` (Space by default) toggles, Shift+Arrow moves and toggles, Shift+Space selects from the most recently selected option to the active one, Ctrl+Shift+Home/End selects to the first or last option, Mod+A selects all, and in single mode picking the selected option again changes nothing. The same fragment selects in two dimensions and in ranges: `mode` may be `range`, `extend: 'range'` makes Shift+Arrow extend from the most recently selected key instead of toggling, `selectable`, `compare`, `between`, `resolveRange` and `all` let a grid define its own order and its own cells between two keys, `extension` and `gesture` are fields for the extension in progress and for a pointer drag, and the returned step carries the verbs a widget calls from steps of its own, `isSelected`, `edges`, `toggle`, `extend(from, to)`, `selectAll`, `press` and `drag`; the `grid` fragment is the layout of a grid: `createGridLayout({ positions, flags, isExcluded, compare })` builds the rows, the columns and the collection from the key, row and column of every cell, `gridNeighbor(layout, from, intent, wrap)` finds the cell in a direction (`forward`, `backward`, `up`, `down`, `rowStart`, `rowEnd`, `gridStart`, `gridEnd`, `pageUp`, `pageDown`) with the wrap, and `gridBetween(layout, from, to)` lists the cells between two keys in reading order; `typeahead({ active, typed, strategy, enabled })` finds an option by its typed letters, cycles through the options starting with a repeated letter, keeps the buffer while its timer runs and drops it when the focus leaves
  - A part may carry a `live` channel, CSS variables and attributes that change on every frame, like the offset of a drag, and a `props` channel, the properties and methods of the element, like `indeterminate`, or `invalidAs`, the attributes of a native input that would be invalid the same way, which the adapter turns into the message of the browser through `setCustomValidity`, each with a selector of its own, built with `shape.part(select, render)` like the part, so the renderer gets the typed selection. The DOM adapter writes them itself after every dispatch and on `flush`, only when the selection changed, on the elements registered with the part, without a render of the framework. A part may register many elements under one name, each with a key, like the panels of tabs: `setPart(name, element, part, key)` hands the key to the selectors, and `connection.paint(element)` writes the channels of one element again, after a framework rendered over them; `props` cannot write `value`, `checked`, `open` or `selected`, which the browser and the parent own
  - `pointer.enter` and `pointer.leave` arrive once per part or item the pointer crosses, from `pointerover` and `pointerout`, with the `pointerType`, and a leave carries the part the pointer moves to as `to`, so a tooltip stays open while the pointer moves from its trigger onto it and ignores a tap. `act.watchKeys()` and `act.unwatchKeys()` bring the keys pressed anywhere on the page to the steps, like `Escape` for a tooltip opened by hover; a key inside the widget's roots or one another widget handled is not delivered twice. `reading(read, fallback)` observes a value from outside the page with `read(options)` before every dispatch, like whether a group of tooltips is warm, so the step stays pure. The attribute that starts the animations `awaitAnimations` waits for belongs to the `live` channel: a framework may render later than the adapter reads the animations
  - The options of a widget are typed: `OptionsOf<typeof shape>` is the declared options plus `x`, `defaultX` and `onChangeX` for every owned value, so a typo in an option, a wrong mode or a callback of another type is a type error at `createWidget`, `simulate` and `useWidget`
  - `connect(instance, elements, { onError })` is the DOM adapter: `connection.listen(root)` or the `keydown`, `click`, `pointerdown`, `pointermove`, `focusin`, `focusout`, `input` and `toggle` handlers attached by a framework for the `connection.events` the widget declares. It builds the inputs from events (`keyInput`: `Spacebar` is Space, Ctrl+A on a non-Latin layout is read from `code`, composing keys are skipped), maps the arrows through `aria-orientation` and the writing direction of the root (without `aria-orientation` a `grid` or `treegrid` role is a grid, a `tablist`, `menubar` or `toolbar` is horizontal, as their implicit ARIA orientation), finds the item key through `elements.keyOf`, and yields to the browser inside text entry for caret keys and printable characters and for a key from a control inside an item whose popup is open, `aria-expanded="true"` or an open popover or dialog in the item. The user's handler runs first: an event with `defaultPrevented`, or one an inner widget already handled, is skipped, also when a framework delivers the same event to two handlers or when its target is outside the root in the DOM, and `handled` on keydown and click makes the handler return `true`: the caller prevents the browser default through its own event, `listen` on the native one, so the handlers of a framework above the widget see `defaultPrevented`. Before every dispatch the adapter reads the observed browser values and `focused` and hands them to the widget with the input, so one event is one commit. The orientation and writing direction of the root are read on every key, so a `dir` changed on an ancestor applies at once. A pointer press owns the pointer until release through document listeners, a move of the pressed pointer is `pointer.drag` with its `point` and `pointerType`, and only a widget that declares `pointer.dragOver` gets the key under the moving pointer and pays for the hit test, `buttons === 0` on move counts as a release, a focus moving between two items inside the root is `focus.move`, a focus leaving the root cancels a pointer press, timers fire back as `timer(name)` inputs, `connection.send(input)` dispatches an input without an event and runs its actions, `connection.observe()` reads the observed browser values before a framework calls `setOptions`, so a `lifecycle.options` step sees the browser as it is, an action that throws is reported to `onError` and the others still run, an action that cannot run yet (focusing an element that is not rendered) waits and is retried with `connection.flush()` until it runs, a later focus replaces a waiting one, a waiting action is dropped when its key leaves the collection or the focus leaves the root, while an action for a key the collection never had, like the next page of a virtualized grid, waits for the key to register, a `focus` whose element did not take the focus, like a cell in an `inert` page, keeps waiting and runs once it can, a focus the connection moved itself is not dispatched back, and `disconnect()` removes every listener and timer. The adapter listens to the page, the document, the window and the `ResizeObserver` of the roots, only once a root registers, so a connection made on the server or for a render that never commits, like the first of the two a strict mode runs, touches nothing. `createElements()` is the registry of the roots, the named parts and the items by key that the adapter reads (`rootOf`, `keyOf` and `partOf` an element). `setRoot(element, name)` registers one more root, like a popover content in the top layer apart from its trigger; each root is the part of its name, an event inside any root belongs to the widget, the nearest root gives the key and the direction, a focus moving between two roots stays inside, and an event that bubbles through two roots of one widget is dispatched once. `setItem(key, element, data)` keeps data with the element, `entries()` lists the items in DOM order as `{ key, data }`, without the elements, so a widget's options stay plain data, cached until an item registers or a registered element is added, removed or moved in the root's subtree (a `MutationObserver` on the root follows reorders; a text change does not re-sort), and `version` with `subscribe` let a framework rebuild its collection from the DOM; `within(container)` lists the keys of the items inside an element, like the cells of the page that scrolled into view
  - `simulate(widget, options, { orientation, rtl })` from `@vega-ui/core/test` drives a widget in node: `send(key.arrowDown)`, `pressAt(key)`, `type('da')`, `setOptions`, `observe`, with strict invariants, refusing an input from a browser event no step declares, also a form reset, a resize or a selection change the adapter follows on the page itself, or a key no step reads, which the adapter would never deliver
  - A drag can take the pointer from the page: `act.claimPointer()` keeps a touch from scrolling the page or the content under it until the release, through a `touchmove` listener on the root that a framework attaches with `passive: false` before any touch starts, as iOS decides at the start of a touch whether a page may hold its scroll and swallows the click that ends the press on the widget, and a press on the page clears it, so a drag that ends without a click does not eat the next tap. - 9dcbb8e: New `Toast`, `ToastRegion` and `ToastClose`, with `createToastQueue` and `useToastContext`.

  - `createToastQueue<Content>()` makes a queue you keep in a module of your own, with no provider: `add(content, { timeout })` shows a toast from anywhere, React or not, and returns its key, `close(key)` closes it. A toast without `timeout` stays until it is closed.
  - `ToastRegion` shows the toasts of a queue as a named `role="region"` live region in the top layer, mounted before the first toast so the screen reader reads every one. It renders its children once per toast as a template that reads the toast with `useToastContext()`, shows the `limit` newest toasts (3 by default) and keeps the older ones waiting. `placement` puts them at the top or the bottom edge, at the start, centered or at the end (`top-end` by default), always centered on a narrow screen. Over an open modal `<dialog>`, `Dialog`, `Drawer` and `Sheet` included, the region moves into the dialog, so the toasts stay above it and the user can still press them.
  - The timers pause while the pointer or the focus is on the toasts, while the window has no focus and while the tab is hidden, and run on with the time they had left.
  - The toasts stack as a deck that expands while the pointer or the focus is on it. A swipe in one of the `swipeDirections` (by default toward the edge the toasts sit at and the nearer side edge, which follows a right-to-left page) closes a toast once it goes far or fast enough, and resists and springs back the other way; Escape closes the focused toast, and the focus moves to the next one, or back to where it was before the toasts once the last one closes.
  - `Toast` is one toast, `role="status"` by default; pass `role="alert"` for an urgent one and name it with `aria-labelledby`. `ToastClose` closes its toast after your `onClick`, unless it calls `preventDefault`, and takes your own button with `asChild`, like an Undo that also dismisses.
  - The styles move with springs and fall back to a fade with reduced motion. `--toast-inset`, `--toast-gap`, `--toast-peek`, `--toast-br-ratio`, `--toast-radius` and `--toast-shadow` on the region tune the look. The state is in `data-expanded` on the region and `data-index`, `data-front`, `data-status`, `data-swiping`, `data-swipe-direction` with `--toast-index`, `--toast-offset`, `--toast-height`, `--toast-front-height`, `--toast-swipe-x`, `--toast-swipe-y` and `--toast-release-duration` on each toast.
  - `@vega-ui/widgets/toast` is the framework-free queue and widget behind them.
  - `@vega-ui/core` adds `act.restoreFocus()`, which focuses again the element that had the focus before it entered the widget, `act.pauseTimer(name)` and `act.resumeTimer(name)`, which keep the time a timer has left, `act.awaitAnimationsAt(key)`, which answers `browser.animationEnd` with the `key` once the animations of an item have finished, `browser.inactive` and `browser.active` when the window loses or regains the focus or the tab is hidden or shown, and `stayOnTop(container, popover)`, which keeps a popover above the other top layer elements and moves its container into the topmost modal dialog and back.

  `@vega-ui/tokens-core` adds `--black-shadow-strong`, a dark shadow with a sharp edge, and the dark theme gives it to `--surface-shadow`, so menus, popovers, dialogs and toasts stand out from the page and from a surface of the same color under them; the light theme keeps its shadow.

- 4ceaa2e: `SnapScroller` takes `orientation='vertical'`, typed `SnapScrollerOrientation`: the items stack in a column, the scroller snaps along the block axis after its `scroll-padding-block-start` and marks itself with `data-orientation`. The `snap-scroller` widget takes the same `orientation` option, and `SNAP_TO` takes `'animated'`: the scroller scrolls to the item over its own `animation-duration` and `animation-timing-function` and reports the item it stops at, even the one it started from.

  New `WheelPicker`, `WheelPickerColumn`, `WheelPickerOption` and `WheelPickerFace`: columns of options that turn like wheels around one selection band, for a time, a duration or a value with its unit. Each column is a `spinbutton` and a vertical `SnapScroller` in one element, with its own `value`, `defaultValue` and `onChangeValue`, scrolls with native scroll snapping and turns with ArrowUp/ArrowDown, PageUp/PageDown, Home/End and typeahead; `loop` makes it go on past the last option to the first one, repeating the options 15 rows past each end. Disabled options are skipped. `size` on `WheelPicker`, `xs` to `xl` and `md` by default, sets the rows and the text like the fields of the same size. The wheels bend into a cylinder with scroll-driven animations where the browser has them and from the scroll position elsewhere. An option is a row that stays in place as a stop of the scroll, and what it shows goes in its `WheelPickerFace`, which bends along the cylinder: browsers stop a scroll by where an element is drawn, so one element cannot be both. A `WheelPickerFace` without children shows the text of its option, its `label` or `value`. The new `wheel-picker` widget holds the column logic.

  `SnapScroller` and `IndexedSnapScroller` measure their items in layout pixels while an ancestor is scaled, like a popover in its opening animation: the scroller used to open a few pixels off and snap to a neighbouring item. The core measure reports `offsetWidth` and `offsetHeight` of a scroller for this, and an element with `role="spinbutton"` reads its arrow keys as plain keys, like a horizontal widget. The new core action `act.animateScroll(part, options)` scrolls a part over its `animation-duration` and `animation-timing-function` without snapping, stops when the user turns the wheel or presses, and answers with one `scroll.end`. The core action `act.scrubWithScroll(part, { keyframes })` drives a paused animation of a part by its scroll, for browsers without scroll timelines; `act.stopScrub` stops it. Several widgets can share one element: `act.send(part, input)` reaches every widget whose root is that part, and `registryOf` becomes `registriesOf`, which lists them.

  `TimeField` picks the time on wheels: `TimeFieldTrigger` opens a `Popover`, and `TimeFieldColumn` with a `unit` of `hour`, `minute` or `second` inside a `WheelPicker` shows the time of the field, goes by `step`, disables the times outside `min` and `max` and writes the time it turns to into the input. The children of a time column are the required template of its options: `<TimeFieldOption><WheelPickerFace /></TimeFieldOption>`, a `WheelPickerOption` with its face for your own class, style or content, with the option read through `useTimeFieldOptionContext()`. A `WheelPickerOption` with neither text nor `label` announces its `value`. `TimeField` takes `disabled` and `readOnly` for the input, the trigger and the wheels. `WheelPickerColumn` takes `autoFocus`. The `time-field` widget takes `PICK_VALUE` and exports the wheel helpers `getTimeWheelOptions`, `getTimeWheelValue` and `pickTimeWheel` with the type `TimeFieldUnit`, which `@vega-ui/react` re-exports. `DateTimeField` picks the time on wheels too: `DateTimeFieldColumn` with the same `unit` turns the time of the date and keeps the day, goes by `timeStep`, takes `today` within `min` and `max` for the date of an empty field and disables the times outside `min` and `max` on their days; its options use `TimeFieldOption`. The calendar and the time wheels of `DateTimeField` share one popover, like the picker of a native `<input type="datetime-local">`: picking a day in `DateTimeFieldCalendar` writes it and keeps the popover open for the time instead of closing it, and `DateTimeFieldCalendar` is no longer a `role="dialog"` of its own; set `role="dialog"` and the name on `PopoverContent`. The time goes on a button under the calendar, as on iOS: `DateTimeFieldTime` shows the time of the field, or its `placeholder` while there is none, for the button that opens the wheels in a nested popover, and the `date-time-field` widget exports `timeOf`. A `Popover` that closes with the focus still inside returns it to the element it came from, since the browsers leave it inside a nested popover, also when the browser drops that focus before the `toggle` event, as Firefox does on a busy page. The popups follow the size of their field: `WheelPicker` takes the size of the field around it unless it has its own, and `DateFieldCalendar`, `DateRangeFieldCalendar` and `DateTimeFieldCalendar` take it on the same scale unless they have their own `size`, so the calendar of a field of the default `md` size grows from `xs` to `md`. `PICK_VALUE` of the `date-time-field` widget takes a full date and time as well as a day, and the widget exports `getDateTimeWheelOptions`, `getDateTimeWheelValue` and `pickDateTimeWheel`.

  `PopoverContent` starts its opening animation together with its children: the fade and scale ran on the compositor while the children were still rendering, so heavy content such as wheels showed an empty box first.

### Patch Changes

- a876533: Every option key gets its own element id. Before, keys like `a.b` and `a_b` got the same id, so `aria-activedescendant` in `Listbox`, `Select` and `Combobox` could point a screen reader to the wrong option, and keys with `'`, `(`, `)`, `!`, `~` or `*` produced ids with those characters.
- b9abf4a: What an invariant, the collection of new or observed options, a part's selector or the adapter's painting throws reaches `onError` like a step's error: outside strict mode the widget keeps its previous state, drops the actions of a commit that failed, `render` keeps the attributes it rendered last, and the adapter still paints the other elements. `ConnectionEnvironment.onError` takes the action as optional.
- b9abf4a: **`Grid` click after a drag.** A drag selection that ended outside the grid left it waiting for the click that ends a drag, so the next click on a cell without a press, like one from a screen reader, did not select it. The grid now swallows only the click in the same task as the release, through a zero timer `DRAGGED` of the `selection` fragment.
- a876533: An image root that loaded or failed before its widget connected, for example during server-side rendering before hydration, is now reported to the widget. `AvatarImage` rendered on the server shows its photo after hydration, or its `fallbackSrc` if the photo failed, instead of staying hidden.
- b9abf4a: **Keyboard click after a touch drag.** After a touch drag of a `Sheet` or `Drawer` that the browser ended without a click, the next click inside it was swallowed even when it came from the keyboard or a screen reader, so Enter on the close button did nothing once. The adapter now swallows only a click made by the pointer.
- a876533: A `<textarea>` or a `contenteditable` element inside a component keeps ArrowUp, ArrowDown, PageUp, PageDown and Enter, so the caret moves between lines and Enter starts a new line. Before, a `Grid`, `Listbox` or another component with keyboard navigation took these keys and moved its own focus instead.
- b9abf4a: **A prevented pointer move.** `event.preventDefault()` in an `onPointerMove` handler did not stop the drag of a `Sheet`, `Drawer`, `Slider` or a `Grid` selection for that move, unlike the other events, where the user's handler runs first and a prevented event skips the widget. A prevented move is now left out of the drag; the release still ends it. A wheel stays out of reach: React attaches `onWheel` as a passive listener, so a widget cannot see its `preventDefault()`.
- b9abf4a: **Readable type parameters.** Generic types and functions name their type parameters in words (`Key`, `State`, `Value`, `SelectionMode`, `Multiple`) instead of single letters, so editor hints and the API tables read as `CalendarValue<SelectionMode>` instead of `CalendarValue<S>`. Nothing else changes.
- a876533: A component no longer keeps what it rendered for items that left its collection. Before, a `Listbox`, `Select` or `Combobox` whose options kept changing, or a `Calendar` paged through many months, held on to every item it had ever rendered until it unmounted.
- b9abf4a: **Shift + arrows after the parent changed the selection.** In a multiple `Grid` or `Listbox`, a Shift + arrow after the parent wrote a new value continued the previous extension and dropped the new value: with `[a, b]` extended by Shift + →, a parent value `['g', 'h']` and one more Shift + → gave `[a, b, c]`. The extension now continues only while the value is the one it produced, so the same keys give `[g, h, b, c]`.
- b9abf4a: **Extending a large multiple selection.** Shift + arrows, Shift + Home / End and a drag in a `Listbox` with `multiple` or a multiple `Grid` took time that grew with the square of the selected options: Shift + Mod + Home with 10 000 options selected took about 6 s. The `selection` fragment now looks selected keys up in a set, so the same step takes a few milliseconds.
- a876533: Picking what is already selected no longer calls `onChangeValue`, like a native `<select>`. Before, `Listbox`, `Select` and `Combobox` reported the same value again when an already selected option was pressed in single or range mode, or when Mod+A was pressed with every option already selected.
- cef5d19: `pressAt` from `@vega-ui/core/test` no longer throws for a widget that listens to `pointer.press` but not to `pointer.down`. It sends `pointer.down` only when the widget listens to it, like the DOM adapter.
- b9abf4a: A symbol key such as `key.asterisk`, `?` or `+` matches when the layout types it with Shift: Shift is not compared for a single character that has no case, so letters still tell Shift apart.
- a876533: An error thrown in an `onChangeX` callback no longer leaves the component out of sync. The error goes to the `onError` of the widget, never to the console, and the component still updates, calls the other change callbacks and finishes handling the event. Before, it kept the new value without rendering it, skipped the remaining callbacks, and did not focus, scroll or prevent the browser default.
- b9abf4a: `command<Payload>()(name)` declares the payload a command carries: `createInput` refuses another one, and `input.is(command)` types the payload for the step, so `input.to` of `SELECT_COUNTRY` is a `PhoneCountry` without a cast. `SELECT_COUNTRY`, `SNAP_TO`, `SNAP_INDEX` and the `PICK_VALUE` of `date-field`, `date-time-field` and `date-range-field`, now each typed by its own value, carry their payload types.
- b9abf4a: `state({ parts })` names the parts of a widget, so an action on a part it does not declare, like `act.showPopover('listbx')`, is a type error instead of an action that waits for that part forever. `Action`, `Result` and `Step` take the part names from the snapshot, `act` keeps the literal part name, and a shape without `parts` takes any name as before. The widgets declare their parts.
- a876533: **Starting an empty `NumberField`.** Arrow keys and leaving a field that does not allow empty start at `max` when it is below zero. Before, they started at `0`, above `max`.

  **Turned-down text after the focus leaves.** `NumberField` forgets a number its controlling parent turned down once the focus leaves, like the date and time fields. Before, a later value from the parent was written as the rejected text into the unfocused field (`1.50` instead of `1.5`), with a selection.

  **Read-only grids.** `Grid`, `DayPicker`, `MonthPicker` and `YearPicker` drop a disabled cell from an uncontrolled value also when read-only. Before, a read-only grid kept the disabled cell selected.

  **One writing direction.** The arrow keys follow the `dir` attribute of the page or an ancestor, like the styles of the components and the drag of `Drawer` and `SnapScroller` already did. Before, the keys read the CSS `direction` property, so a page with only `direction: rtl` in CSS got arrows that disagreed with the layout of the same component. Set `dir="rtl"`; the CSS property alone is not supported.

  **After a remount.** A `Tooltip` that was open when its effects ran again, as in `StrictMode` or a hidden `<Activity>`, closes on `Escape`; before, it ignored the key. The letters typed into `Listbox` and `Select`, and a tooltip waiting to show or hide, run out as usual after such a remount; before, their timers were lost.

  **`indeterminate` removed.** A `CheckboxInput` whose `indeterminate` prop goes from `true` to unset is no longer indeterminate; before, it stayed so.

  **Sheet snap point after a close.** `onChangeActiveSnapPoint` of an uncontrolled `Sheet` now also fires when the sheet closes and returns to its default snap point, with that index, so the reported value always tells where the sheet opens next. Before, the return went unreported and the last reported index went stale.

  **Deleting a word.** Ctrl+Backspace (Option+Backspace on macOS) and Ctrl+Delete in `PhoneField` and `NumberField` find the word by the Unicode rules a native text field uses. `PhoneField` deletes the last group of digits (`+1 201 555-0123` becomes `+1 201 555`) instead of everything after the last space. The date and time fields keep deleting one segment, like a native date input.

  **Typed letters after the focus leaves an open `Select`.** The letters typed into an open `Select` are forgotten once the focus leaves, as in a closed one and in `Listbox`. Before, a search typed right after the focus came back went on from the old letters.

  **Plain inputs.** `focus.leave` no longer carries the element the focus moved to as `to`, so every input a step or `onDispatch` sees is plain data.

  **Same options, less work.** A widget keeps its state when it gets new options with the same content, so a re-render with unchanged props no longer reruns its checks or notifies its subscribers.
